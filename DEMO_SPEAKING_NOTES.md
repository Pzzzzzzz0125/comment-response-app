# Comment Response App — Demo Speaking Notes

## Demo setup

- Demo URL: <http://localhost:8010>
- Recommended duration: 7–9 minutes
- Select **San Jose** first.
- Keep one browser tab on the main app and open source citations in the in-app viewer.
- Five minutes before presenting, run the Smart Search question below once so the result is warm.

### Numbers to remember

- The audit dataset contains **378** historical parent comments.
- The production UI currently exposes **255 verified/search-eligible comments**:
  - San Jose: **175**
  - Menlo Park: **67**
  - Sunnyvale: **13**
- Within those 255 records, **74 have manually confirmed responses** and **181 have a verified “no source response found” status**.
- A separate set of **123 Warner PC3/PC4/PC5 comments** remains outside search until its government-comment text passes visual re-verification. Its existing confirmed response links are retained for audit.

## Opening — 30 seconds

> This application turns historical permit-review comments and company responses into an evidence-backed knowledge base. The goal is not to have AI invent a new permit response. The goal is to help a reviewer find relevant historical precedents, understand what was done previously, and verify every claim against the original source.

> The important design principle is evidence first: AI helps with retrieval and explanation, while counts, record identities, response status, and citations come from the structured database.

## 1. City summary — 45 seconds

1. Select **San Jose**.
2. Point to the city summary at the top.

> The first view gives us a quick picture of the selected city: total comments, technical versus administrative comments, projects, review rounds, and common topics. These counts are calculated by backend code, not generated by the language model.

> The interface only counts records that have passed the current data-trust rules. Raw or quarantined extraction remains available for audit, but it cannot silently influence search results or summaries.

## 2. Knowledge Chat — 1–2 minutes

Ask:

> Give me a summary of San Jose comments.

Then explain:

> This is the conversational knowledge layer. It can answer broad database questions, topic questions, comparisons, counts, and follow-ups. The answer is organized into a direct answer, historical actions, supporting evidence, and limitations.

> Gemini is the presentation and reasoning layer. It cannot manufacture record IDs, source locations, or database counts. Supporting comments are selected from the verified data pool, and citations are attached to the underlying records.

Possible follow-up:

> Which disciplines have the most comments, and how many have confirmed responses?

## 3. Smart Search — 1–2 minutes

Switch the city to **Menlo Park** and search:

> How have we handled tree-protection comments?

> Smart Search is Gemini-assisted retrieval rather than sending the entire database to the model. The app first retrieves a bounded candidate set using the local search index. Gemini then analyzes, reranks, and independently verifies those candidates.

> Notice that the results distinguish direct precedents from related records. Raw relevance percentages are not treated as the answer. The user sees the reason a record is useful and any important differences.

Good record to select:

- `C-03831a75b6ddcc07` — direct tree-protection precedent with a confirmed historical response.

## 4. Comment and response detail — 1 minute

Select a result and point to the vertical detail layout.

> The government comment is shown first and the historical company response beneath it. This reading order matches the actual review workflow: requirement first, action second.

> Response labels are deliberately colored. Green means a confirmed historical response. Missing responses remain visually distinct, so the application never implies that an action was taken when no source response was found.

> The original wording is preserved for audit. Display formatting only repairs readability issues such as accidental line breaks; it does not change technical meaning.

## 5. Spreadsheet and source viewer — 1–2 minutes

Return to **San Jose** and use keyword search:

> Inspector's checklist

Select **RS Building Review comment 8.0** for 4155 Mitzi Dr.

> A citation is not a download link. It opens an authorized in-app source viewer at the cited location.

Click the spreadsheet source.

> For Excel sources, the app keeps the workbook structure, opens the correct sheet, scrolls to the cited row or cell, highlights it, and allows the full cell text to be read. It is a read-only evidence viewer, not an Excel editor.

For a PDF example, open a San Jose comment sourced from `26-118703.pdf`.

> PDF citations open on the cited page. The viewer uses stored coordinates when available and falls back to exact-text search. The highlighted evidence remains connected to the source record rather than to a raw filesystem path.

## 6. Data quality and human verification — 45 seconds

> The latest manual rematch covers all 255 currently searchable comments: 74 verified pairs and 181 verified unpaired comments. The import is idempotent, so running it again creates no duplicate responses or links.

> Low-confidence or conflicting extraction is quarantined. It is preserved for investigation but excluded from normal display, Smart Search, Knowledge Chat, and city summaries. This is how the application avoids turning an extraction mistake into a confident AI answer.

## Close — 20 seconds

> The product combines three things: a verified historical data pool, conversational retrieval, and source-level evidence. It helps us answer “Have we seen this before, how did we respond, and where is the proof?” while keeping the reviewer in control.

Then demonstrate:

## Likely questions

**Does the AI write the final permit response?**

> No. It retrieves and summarizes historical evidence. A professional still decides whether a prior response is applicable to the current project and code context.

**Can Gemini invent a citation?**

> No. Source IDs and locations are supplied by the backend source registry. Gemini does not create file paths, record IDs, or page locations.

**Why are only 255 of 378 comments searchable?**

> We found that 123 government-comment fields could contain row-boundary contamination. Their raw records and confirmed response links are retained, but those comments are excluded until the comment text passes the required two-pass visual verification.

**How do you handle comments with no response?**

> They remain useful historical government requirements, but they are explicitly labeled as having no verified source response. They are never used to claim what the company did.

**What happens when a response applies to several comments?**

> The data model supports a verified grouped response. Each parent comment keeps its own identity and source, while the shared response relationship records the human-verified match basis.

**Is the import repeatable?**

> Yes. Imports use stable IDs and conflict checks. The latest workbook was applied twice in validation: the second run created zero responses and zero links.
